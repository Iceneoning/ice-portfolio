# V1 候选作品与证据整理表

> 以下是基于既有沟通整理的**内容候选**，并非本次实际检查了 UE 工程、源代码或素材后的认证结果。标记「待核对」的内容禁止直接作为已证明事实发布。

## 优先级一：RTS Gameplay Systems（主打）

- 类型：Unreal Engine 5.8，RTS 玩法系统。
- 已沟通的个人职责：**地图、建筑、能力、资源**相关系统；需后续在代码/文档中核实实际接口和范围。
- 命令系统：**不是本人制作**。可以准确讲接入或依赖，但不能写成独立开发命令架构。
- 多人网络：曾讨论网络机制，但未完成相应多人测试；网站不得声称已完成多端、延迟/丢包验证。
- 推荐展示顺序：实机功能流 → 四大负责模块 → 关键时序/失败路径 → 真实验证边界。
- 待收集：录屏、建筑/资源截图、本人代码片段、模块接口图、对应的测试报告/Commit。

## 优先级二：Blitz Archive（主打）

- 类型：Unreal Engine 5.7 / Lyra 基座、玩法和能力机制。
- 候选技术：GAS、GameplayTag、DataAsset、Experience/GameFeature、推车规则与网络结构。
- 合适切入：基于 Lyra 如何扩展玩法规则、C++ 逻辑与蓝图表现职责、多人场景下的权威/状态处理。
- **注意：** 要明确“复用 Lyra 既有能力”与“本人扩展的系统”之间的边界；版本、录屏和网络测试数据发布前必须重新核对。
- 待收集：推车实机画面、能力设计图、玩法规则和状态流、网络实际测试记录以及个人贡献证明。

## 优先级三：UE 蓝图开发实践

- 类型：第一/第三人称玩法原型，是否单独成页取决于截图、代码或蓝图逻辑的质量。
- 定位：说明掌握 UE 蓝图、组件与基础游戏逻辑的完整开发链路。
- 优先展示真实 Gameplay、蓝图节点的关键逻辑与个人负责的交互，不用「大型系统研发」等不实夸张措辞。
- 待收集：项目确切名称、版本、演示、最有价值的 2–3 个实践点。

## 优先级四：WHITE FANG 465（技术专题，可在主作品之后）

- 类型：Blender → UE 资产制作管线；**不应冒充 Gameplay 系统项目**。
- 候选展示：建模迭代、UV/材质、骨架/绑定、导入 UE 后的表现问题。
- 注意：此前镜片最终视觉效果未闭环；Stage 8 之后内容不应直接写为「全部完成」。
- 待收集：多角度展示图、对比图、UE 内实机渲染、最终技术验收清单、素材授权。

## 首页初步排序

1. RTS —— 先证明独立负责的技术模块。
2. Blitz Archive —— 展示 UE/Lyra、Gameplay Ability 与游戏机制。
3. 其他项目与资产专题 —— 覆盖蓝图基础和美术技术管线。

以上顺序是可调整的内容决策，**不等于所有项目已达到可发布质量**。优先保证前两项有完整证据，再扩大数量。
