# 视觉设计规范 V1：冰晶折射 × 游戏数字展厅

- 状态：视觉方向提案；**未完成设计稿、未经过用户审美验收**
- 定位：精致、冷静、有电影感；让 UE 游戏实机画面成为主角
- 关键词：层次 / 留白 / 低饱和深色 / 光学折射 / 建筑感 / 编辑式排版

## 设计原则

1. **先有作品，再有特效。** 主视觉必须真实展示作品，不用抽象贴图取代项目画面。
2. **弱化容器，突出图像。** 卡片边框、玻璃和光效是构图工具，不是每个区域都必须套玻璃。
3. **用克制提高质感。** 一页只建立 1 个主要视觉强调点，不做随机星光、满屏粒子、重复泛光。
4. **游戏内容高对比，技术内容高可读。** 大封面负责吸引，架构图和代码负责留下可信证据。
5. **视觉语言与博客有亲缘关系，信息架构和部署完全独立。** 冰晶元素可以保留，但不借用博客动漫封面或文章模版。

## 页面构图

### 首页

- 顶部 Header：紧凑品牌文字、作品、关于、简历；窄屏折叠为可访问的菜单。
- Hero：一条清晰定位（UE Gameplay / C++）、有辨识度的中文短句、一个代表作品视觉、直接通往案例的 CTA。
- Featured Projects：优先展示两个核心项目，交错布局可以，但不能让项目介绍变成难以阅读的装饰字。
- Engineering Focus：能力维度分组（玩法系统、UE 架构、调试验证），而不是铺满技术图标。
- About / Contact：可核实的经历、简历入口、GitHub / 公开联系途径。

### 项目索引

大图 + 明确标题 + 职责摘要 + 技术标签；首屏让用户立即找到项目，而不是看完介绍动画才出现内容。适度不对称，但排序和导航要稳定。

### 项目详情

Hero 主封面 → 简短事实摘要（平台、职责、项目阶段） → 实机演示 → 系统结构 → 核心实现 → 验证和局限。正文最大阅读宽度约 68–76ch，图片/图表可以突破正文列宽。

## 字体和间距

- 标题与正文采用适合简体中文和英文代码混排的字体栈，中文优先使用系统字体 / 稳定子集；如引入可下载字体，先测加载和版权。
- 代码用独立等宽字体；代码块支持换行提示或横向滚动，避免截断。
- 排版采用固定 spacing scale，例如 4 / 8 / 12 / 16 / 24 / 32 / 48 / 72，禁止无规律硬编码。
- 高密度技术页面以舒适行高、目录锚点、清楚的 H2/H3 层级为优先。

## 光学语言的具体实现边界

- 冰晶只用于界面边缘、滚动分隔、少量聚焦状态和艺术背景。
- 折射质感采用图层、背景渐变、细纹理或局部静态图，不用高成本全屏实时折射作为必要功能。
- 游戏截图的色彩不应被统一蓝滤镜吞没；摄影式暗边要保证作品辨识度。
- 任何装饰层不能覆盖点击目标、可选中文本和媒体播放控件。

## 视觉评审标准

- **识别性：** 截去标题后仍有一定辨识度，不能像随意下载的通用 Astro 模板。
- **内容权重：** 第一屏能看见 UE 作品及明确的职业方向。
- **质感：** 动效、阴影、透明度和留白为同一种设计语言服务。
- **可信性：** 界面不会把尚不存在的功能包装成已经完成。
- **一致性：** 首页和案例页是同一系统，既不是两个独立网站，也不破坏案例阅读。
