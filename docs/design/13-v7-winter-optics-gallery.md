# V7 冬日光学展厅（Winter Optics Gallery）— 美术与渲染方案

- 日期：2026-10-08
- 状态：**V7 已完成独立 HTML/CSS + WebGL2 原型并通过 Edge 桌面与 390 CSS px 浏览器导航测试（14/14）；仍未通过用户审美验收，也未并入正式 Astro。**
- 本地入口：`H:\vs_code\ice-portfolio\docs\prototypes\cinema-v7\index.html`；[原型说明](../prototypes/cinema-v7/README.md)。
- 目标：从此前“暗色冰窟 + 实物雪晶贴片”的组合改为**阳光照入冬日空间的纯计算机图形学视觉**，使 Unreal Engine Gameplay 作品集显得清透、明朗、有人的参与感。
- 施工范围：ice-portfolio，第一步为独立 V7 视觉实验与渲染原型，不覆盖 V4/V5/V6 或已建 Astro 源码。
- 基础架构沿用 [静态站设计](../architecture/01-system-overview.md)、[导航交互](07-s1-cinema-navigation-v4.md)、[动效分镜](03-motion-storyboard.md)、[动效运行时](../architecture/04-motion-runtime.md)。
- 最新反馈优先级高于历史 V4 的深冷背景、六角 SVG/实拍晶体材质要求；**保留经用户明确认可的标题、文案和独立项目页导航，不保留已经被用户否定的美术素材。**

## 一、拒绝与保留

**明确弃用**：真实微距雪花 PNG/WebP、暗湖冰、冰窟、黑背景、高对比科技 UI、把巨大雪晶照片挂在右边、无意义的假游戏画面、碎玻璃形状凑数、满屏粒子、长时不可跳过开场。保留历史文件仅供对比，不应被 V7 产品引用。

**保留**：
- 主标题「让规则凝成世界。」与「凝固一瞬光，构建一个世界。」、\`From systems to playable worlds.\`。
- 分区「作品选集。」以及「选择一个项目，进入独立的作品页面。了解玩法目标、个人职责与技术实现。」
- 首页像展厅前厅：点项目海报/卡片切换 **独立 URL** 的案例页面，而不是原地展开长文。
- 两部案例必须在**首屏与页尾**都可以直接「下一部作品」，能返回选集，链接不开 JS 也工作。
- RTS：只写本人负责的地图、建筑、能力、资源；既有命令系统标明非本人开发；不能把尚未完成的多人实测描述为已验证。
- Blitz Archive：Lyra/GAS 框架能力和本人扩展区分；验证结果须有真实项目材料支撑。

## 二、视觉宣言：清晨透光，而非深夜冰洞

**气质关键词**：初冬日光、晶莹、温暖的留白、可触摸的玻璃、安静而有回应、创作者的工作展台。

主背景采用由天空蓝至雾白/暖白的纵向色温梯度，局部出现青蓝或金色的极弱焦散。**浅背景上的正文必须使用深墨色**，不能把白字照搬 V6。

| Role | 起始 Token | 使用规则 |
| --- | --- | --- |
| 底色 | \`#eff8fa\` → \`#d9edf2\` | 全站默认空气感、避免纯白刺眼 |
| 阳光扩散 | \`#fff4df\` | 局部右上光源，不覆盖大段正文 |
| 雾青 | \`#a5dce1\` | 折射面边缘与弱光 |
| 薄冰蓝 | \`#7cb7cf\` | 光学细节与少量交互 |
| 墨蓝文字 | \`#173446\` | 主标题和正文主色，确保对比 |
| 次要字 | \`#526f7c\` | 辅助元数据；逐项验证对比度 |
| 温暖点睛 | \`#efc8a4\` | 太阳的温度，小面积非品牌橙色 |
| 卡片表面 | \`rgba(255,255,255,.62)\` | 只在保证字色对比后使用 |

上表是**起始色彩探索**，浏览器视觉与对比度验证后允许调整，不自动认定满足 WCAG。

## 三、页面构图

### 首页 Hero

- 左侧 57–62% 组织标题、职业、说明与「进入作品展厅」主 CTA。主标题有两行大尺度文字：**让规则 / 凝成世界。**
- 右侧 38–43% 不是“独立装饰卡片”，而是一个虚拟**折射窗**：CG 的几何晶片与光场位于空间中；上方近光、下方投影/焦散接入页面背景，视觉上有光照的来源与去向。
- 背景底图不是贴图，而是 CSS 的天光、暖白、雾色；程序化渲染只占非正文的光学区域。材质效果须能被移除后页面仍美观。
- 可以使用极短的“欢迎来到我的作品展厅。”作自然引导，但不能遮盖工程师定位，不添加未经核实的履历。

### 作品选集

- 不使用无授权/不真实的游戏截图，也不使用假想山景或作为作品画面的 CG。
- 每部作品做“展签 + 编号 + 项目名称 + 技术事实”组成的编辑式视觉卡，轻柔光学细边、最少一次 hover/focus 反馈。
- 项目名称应比装饰显著，按钮含**具名动作**：如「查看 RTS 案例 ↗」，不要仅使用抽象箭头。
- 真实 UE 图片准备好后直接在预留媒介框展示。暂缺则标注“游戏实机画面待补”，不拿 CG 雪晶伪装成 UE 项目成果。

### 项目详情

- 面向面试官快速判断：页首具名的「返回作品选集」与「下一部作品」，项目定位、引擎、个人贡献、阶段。
- 正文侧栏按项目背景 / 系统关系 / 个人贡献 / 验证状态组织。
- 页尾重复「下一部作品」；任何深度位置的读者都能无需返回首页换片。
- 与首页共享早晨光色和细折射边缘，**细节页减少背景动态至约 20%**，确保代码与架构图可阅读。

### 移动端

- 内容优先：标题 → 英文小标题 → 职责简介 → CTA → CG 光学画面。
- 只在小尺寸区域中渲染晶体，不允许粒子覆盖按钮与正文；性能紧张时停止 Canvas 改用 CSS 降级。
- 390 CSS px 起不出现横向滚动。鼠标指针不应是动画成立的前提。

## 四、图形学实现模型（从能说清的物理原理出发）

| 技术 | 作用 | 初期实现 | 与物理的关系 |
| --- | --- | --- | --- |
| Fresnel（Schlick 近似） | 让倾斜面边缘反射加强 | GLSL \`F = F0 + (1-F0)*(1-dot(N,V))^5\` | 仅近似介质界面反射率；不是完整路径追踪 |
| Specular | 晶面迎光时出现小面积亮斑 | 定向光 + 法线 + 高次幂/近似微表面 | 视结果决定是否改用 GGX，不能把均匀 glow 叫高光 |
| Refraction | 晶体内部对背景产生偏移 | 可控采样偏移 + 弱色散或图形层错位 | 屏幕空间视觉近似，不等价于真实多次折射 |
| Crystal facets | 有厚度感的几何晶体 | 程序化三角面 / 局部 SDF 距离与解析法线 | 法线必须跟几何/隐式面一致，不能独立胡乱描边 |
| Caustics | 阳光透过结构投下局部波纹 | 非均匀频率的光场干涉 / 噪声 + 聚焦亮带 | 属于艺术近似，不宣称满足能量守恒的真实焦散积分 |
| Scattering | 给空间空气与温度 | 大尺度雾梯度 + 少量柔光卷积层 | 2.5D 近似，不是体积光传输计算 |
| Film grain | 减少纯渐变“PPT”感 | 静态或时间无关的低振幅噪声 | 不应出现动荡噪点或压缩伪影 |

### 实际分层架构

\`\`\`text
Semantic HTML / Astro SSG     标题、案例、按钮；永远先渲染
└── CSS Design Tokens          天光、暖白、排版、Frosted UI & 降级
    ├── CSS gradients          环境光源、空气透视和分区明暗
    ├── WebGL2 canvas          只管 Hero 光学区域的动态晶面（可省）
    │   ├── fragment shader    晶体法线 + Fresnel + 定向高光 + 低对比焦散
    │   └── uniforms           time, resolution, pointer, reduced-motion
    ├── CSS hover/focus        卡片仅亮边、轻微位移
    └── native links           跨文档作品切换，保持浏览器历史
\`\`\`

**WebGL2 作为独立的、可失败的提升层**，不能作为首页正文、导航、按钮的运行前提。第一版可选 SVG 静态微几何降级；若 WebGL 无效就保留同一暖冬光色的 CSS 布景，不显示报错。

### 交互节奏

- 初次进入：内容立即可见；允许 400–700ms 的一次性光场渐入，不阻塞页面。
- 空间光场：移动极缓慢、幅度极小；晶体不得每秒持续剧烈自转，不出现屏保感。
- hover/focus 项目：卡片边缘亮起、具名箭头轻微移动；\`prefers-reduced-motion: reduce\` 不执行光场时间更新。
- 跨页切换：基线为原生 \`<a href>\`；浏览器支持时再实验跨文档 View Transition，不影响返回。
- 不为“活人气氛”增加飞来飞去的假 NPC、表情包或雪粒。温度来自留白、柔光、真实工程内容、交互反馈。

## 五、技术与性能预算

- 首版仅在首页 Hero 创建 1 个 WebGL2 canvas；**不建立全站常驻渲染循环**。详情页 CSS/静态优先。
- 设备像素比：桌面可限 \`min(dpr,1.5)\`，低性能设备 1；Hero Canvas 渲染分辨率应有像素面积上限并按需缩放。
- \`requestAnimationFrame\` 只在页面可见、未请求 reduced-motion、确实需要运动时运行；失焦或不可见时暂停。
- 再开：WebGL2 \`webglcontextlost\` 及时降级，无限重试禁止；异常不影响语义页面。
- 页面主体无 JS 必须能访问案例；小尺寸或性能不足时省略 Canvas；禁止背景 GPU 占用阻塞正常滚动。
- 预期：在目标硬件检查稳定帧时间，而非凭空宣布 60FPS；必要时 30FPS/静态化，实际测量后再做结论。
- Shader 不得有未界定步长的 ray march；复杂度与设备负担随实际评审减法优化。

## 六、验证流程和关卡

1. **S7-A：方向文档。** 本文与明确的 CG/光学分层合同落盘。
2. **S7-B：独立可预览原型。** WebGL2 光学画面 + CSS 暖冬 Hero + 作品卡 + 两个详情页，绝不覆盖 V6/正式 Astro。
3. **S7-C：桌面/手机真实浏览器视觉复核。** 检查截图、CG 质量、实际链接、降级、对比度、无横向溢出、reduced-motion。视觉不满意就返回 shader 调光与版式，而不是上真实照片。
4. **S7-D：用户审美评审。** 确认是否不再压抑、是否真有玻璃光、是否具有冬天辨识度；没有用户确认不得把“构建成功”等同于“美术通过”。
5. **S7-E：迁移 Astro。** 用户确认后再把 CSS/WebGL 局部组件化；正式 Astro build/TypeScript、性能与无障碍仍单独验收。

## 七、明确不做与风险

- 不恢复真实雪晶 PNG/WebP（包括 logo、CSS background、样式伪元素），不拿旧雪晶 SVG 作为“新晶体渲染”冒充。
- 不强迫安装 Three.js / React。初期独立 WebGL2 原生顶点 + 片元着色器更利于受控实验；如果质量复杂度证明需要 3D 资产，须记录决策再追加。
- **风险：** 基于简化 GLSL 几何 + Fresnel 的晶体很容易像廉价矢量广告。验收依据是实际截图与审美反馈，而不是“shader 已经用了 Fresnel”。
- 背景即使更亮也必须维护正文对比度；玻璃霜面可以半透明，**正文容器不允许为了效果牺牲可读性**。
- 美术方案只涉及冰晶 / 冬日环境。**真实 UE 游戏截图仍然是作品案例的必要内容**，但不能由假渲染图替代。
