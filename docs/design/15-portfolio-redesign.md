# Winter Studio：作品集重新设计

2026-10-09，Asia/Hong_Kong。用户明确要求重新设计，认为之前的审美不适合作品集。本约定接替 14 号文档的视觉部分；项目事实、原生路由、真实媒体及安全边界继续有效。

## 设计目的

让访客首先理解作者的 UE / C++ Gameplay 方向、有哪些项目、个人负责什么，再进入独立案例查看系统边界与验证状态。保留「让规则凝成世界。」和「作品选集。」以及明亮冬日气氛。

## 视觉语言

- 冰白与微冷灰背景，深墨色正文和标题，低饱和蓝绿作为强调。RTS 封面为浅蓝，Blitz 为浅暖灰，形成轻微区分。
- 统一无衬线文字；等宽字体只用于项目编号、引擎及英文栏目标签。移除大字斜体、衬线混排、缩进标题与大面积光晕。
- 标题、说明、项目索引、正文形成明确字号层级；功能性小字提高对比度。页面主体宽度上限 1200px，空间服务于分组和阅读。
- 雪花作为 30px 左右的原创品牌标记使用，不再占据 Hero 的大面积主视觉。上一轮 Shader 不进入当前页面资源链。

## 页面结构

- Header：ICE / Gameplay Engineer、小型雪花、作品与关于导航。
- Hero：左侧身份 / 标题 / 介绍 / CTA，右侧由 Content Collections 驱动的项目索引，可直接进入 RTS 和 Blitz。手机纵向排列，项目入口紧接介绍。
- 作品选集：两列卡片，手机单列。文字封面明确标注实机画面待补，下面展示名称、职责方向与关键词。已有媒体审核逻辑继续生效；未来可换入真实截图，不修改路由。
- About：说明作者如何组织技术案例，以及真实材料待补状态。
- 案例页：首屏具名换片、标题 / 项目说明、紧凑的媒体待补提示、职责元信息；正文保留 MDX 与自动目录；页尾再次提供换片和返回作品。
- Footer：品牌、技术方向、返回选集。

## 交互与内容边界

原生链接和 HTML 支持基础浏览；当前页面不加载 JS / canvas。反馈限于卡片抬升、边框和箭头变化，降低动效偏好下关闭。键盘焦点清楚可见。装饰圆弧不表示任何游戏系统实现、地图或实机画面。

RTS 的命令系统归属、尚未完成多人测试，Blitz 的 Lyra / GAS 与个人扩展边界保持原文。未伪造媒体、性能数字、联系信息、源码链接或验证结果。将来素材补齐后，网站展示效果还需随真实项目图重新检查。
